# Qwen Cloud Token Plan: step 1 capability evidence

## Step 3 transport addendum (2026-09-17)

The dedicated gg-ai adapter and dispatch now exist; the preparatory statements below describe step 1, not current transport availability. Runtime credential discovery, native storage/testing and UI remain out of scope.

Re-fetched the official [thinking guide](https://docs.qwencloud.com/developer-guides/text-generation/thinking.md), [GLM guide](https://docs.qwencloud.com/developer-guides/third-party-models/glm.md) and [DeepSeek guide](https://docs.qwencloud.com/developer-guides/third-party-models/deepseek.md). Qwen's `preserve_thinking` defaults to false; GLM `clear_thinking` defaults to true for 5.3 and false for the other GLM models. The adapter leaves both fields absent, preserving those model-specific defaults, while roundtripping assistant reasoning in its separate original `reasoning_content` field. It does not force preserved thinking across all models.

Transport accepts only an explicitly supplied locally validated Token Plan key (7–256 ASCII identifier characters including `sk-sp-`), exact internal model identities and bounded integer output limits. It rejects caller endpoint/header/fetch overrides, uses the installed SDK with logging/retries disabled, and rebuilds the final POST to the fixed endpoint with redirect refusal. Streaming remains enabled even when a caller requests a non-streaming recovery: there is no alternate transport/provider fallback. The whole request has a 120-second cancellation deadline. Only fixed local error messages escape; raw SDK causes, response headers and bodies are discarded. Controlled-fetch tests are not live endpoint or entitlement verification. The OS trust store and host network/fetch implementation remain trusted; this does not protect a compromised host.

Checked 2026-09-17. This is a policy matrix, not a registered catalogue or working connection. Source URLs and provider policy live in `packages/gg-ai/src/qwen-cloud-policy.ts`, exported by gg-ai and reexported through `packages/gg-core/src/qwen-cloud-token-plan.ts`. The approved plan remains authoritative for scope and conservative thinking choices.

## Evidence and interpretation

- Token Plan quick start fixes the inference destination to `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1/chat/completions`, the key prefix to `sk-sp-`, and distinguishes the plan from PAYG. No alternate endpoint is defined here. Prefix is a key-type hint, not authentication.
- Token Plan overview supplies the exact eleven-model allowlist. Internal IDs always prefix the wire ID with `qwen-cloud/`; direct GLM/DeepSeek identities remain untouched.
- Text generation specifications, Qwen3.8/3.7/3.6 tables: all five approved Qwen IDs have 1M context; Qwen3.8 has 128k output, Qwen3.7/3.6 have 64k output.
- The same page's DeepSeek table gives all four approved IDs 1M context and 384k output. Its footnote explicitly shares that output budget across thinking and answer. It must not be treated as 384k answer plus another reasoning budget.
- GLM guide's Quick start gives both GLM models 1M context. Model releases, August 28 GLM-5.3 entry, gives 128K maximum output. The authoritative [GLM-5.2 marketplace page](https://www.qwencloud.com/models/glm-5.2), under Rate Limits & Context, gives Max Input 1M, Max Output 131K, Max Input Thinking 1M, Max Output Thinking 131K, Context 1M, and Max Reasoning 131K. The matrix therefore uses 1,000,000 context and conservative 131,000 output tokens for GLM-5.2.
- The [Chat Completions schema](https://docs.qwencloud.com/api-reference/chat/openai-chat.md) defines GLM-5.3 `max_tokens` as the combined answer and reasoning budget. GLM-5.2 uses the same combined budget when `thinking_budget` is omitted, as this policy requires. Both GLM entries therefore use `reasoning-and-answer`; the reasoning allowance is not an additional output budget.
- Units: the text specifications use abbreviated 1M/k and say 1M is roughly 750,000 words; they do not establish binary multipliers. The release description for DeepSeek V4 Pro 0813 says “1 million tokens.” Use conservative decimal values (1,000,000; 128,000; 131,000; 64,000; 384,000), not an assertion that the vendor guarantees exact binary capacities.
- Thinking follows the approved matrix: Qwen3.8 off/low/medium/xhigh; Qwen3.7/3.6 off/on; GLM5.3 low/high/max with no off; GLM5.2 and original DeepSeek V4 Pro off/high/max; dated DeepSeek and V4.1 off/low/high/max. The current GLM5.2 guide expands efforts; the approved narrower subset is intentional. No policy emits `thinking_budget`, avoiding Qwen3.8 effort/budget conflicts. Normalization and preserved-reasoning request behavior belong to later steps, not this module.
- Image advertising is conservatively false throughout this preparatory matrix until the Qwen adapter and existing attachment handling are verified together. This does not assert that all upstream models are text-only. Specifically, keep Qwen3.7 Max false: the Token Plan overview says text-only despite newer multimodal snapshot documentation. Do not infer plan capabilities from snapshots.

Evidence includes the official GLM, text-model and release Markdown pages plus the authoritative marketplace and Chat Completions schema findings supplied for this correction. General API examples contain PAYG destinations: those are not policy inputs. No credential, live inference, endpoint-connectivity test, or entitlement check was performed.

## Contracts and scope boundaries

The shared status/result types contain only closed status/error values, no saved-key readback, raw upstream message, arbitrary endpoint, remaining Credits, reset estimate or dollar estimate. Types alone do not sanitize runtime input: native and daemon boundaries must construct/validate these payloads in later steps. A locally saved key must remain `not-tested` until an explicit user-operated test succeeds.

gg-ai owns provider constants and the capability matrix so a future adapter needs no import from gg-core. gg-core reexports that policy via `@kenkaiiii/gg-ai` and retains only the native status/result contracts. These exports do not add the provider to the Provider union, gg-ai dispatch, runtime auth resolution, MODELS, native commands or UI. Default is Qwen3.8 Max; fast/summary policy selects Qwen3.8 Flash, within the same provider and route. These are declarations only, not fallback activation.

Working-tree recheck found the existing gg-ai types change was only the defaultHeaders documentation; AgentPane and native lib.rs had no diff. Existing programmatic/provider changes were preserved. Existing gg-core registry/auth tests cover registry invariants and shared-file credential concurrency/dual-credential isolation; the new tests verify policy without enabling registration.
